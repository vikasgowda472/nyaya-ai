# Supabase database migrations

Apply migrations in filename order through the Supabase CLI or Dashboard SQL editor. The application is not connected to a Supabase project from this repository, so migration application must be performed against the intended project by an authorized operator.

## Phase 3 reviewer workflow

`202609120002_reviewer_audit_workflow.sql` adds append-only provision review events and database-side workflow enforcement:

- New records must begin `pending`.
- An approved provision cannot have its legal text, citation fields, tags, or summary changed unless it is returned to `pending` review in that update.
- An approval must name the authenticated reviewer through `reviewer_id = auth.uid()` and include `reviewed_at`.
- Review events are generated by triggers; authenticated users cannot insert, edit, or delete audit rows directly.
- An official source used by approved authority cannot have its URL, version, or title changed; a new source version is required.
- Only `reviewer` and `admin` profiles can read the audit history. Role assignment remains an operational Supabase task and must never be exposed through the public app.

## Phase 5 source intake and privacy

`202609120003_source_intake_and_privacy.sql` adds official-source intake requirements and separate private-incident storage:

- A provision can be approved only with review notes and a SHA-256 fingerprint matching its exact text.
- `private_incidents` uses owner-only Row Level Security. Reviewers and admins have no policy granting access to another user's incident records.
- The reviewer dashboard works only with legal source tables and never queries private incidents.

## Phase 6 approved-corpus publishing

`202609120004_approved_corpus_contract.sql` records the reviewer name with each new approval. FastAPI reads approved corpus data only when its server environment contains `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. The service-role key must never be placed in `.env.local`, a `VITE_` variable, browser code, or Git.

Before applying to production, test every migration on a Supabase staging project with both a standard user and reviewer account. Verify a standard user cannot access source records, a reviewer cannot access private incidents, and FastAPI returns a refusal when no complete approved authority exists.
